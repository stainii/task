What to look for

  • The one real conflict, and the reason for the first rig switch. ADR-0006: "everything overdue or due today is always visible, however many that is". Postponing an overdue task makes it overdue and not started. Both rules cannot win.
    sleeps until its start date — postpone works, and the always-visible rule acquires an exception you granted by hand, one task at a time.
    stays in Due today anyway — the rule is absolute, and postpone silently does nothing for the tasks you most want to postpone. Try postponing Onderhoud ketels under it.
  • The due date never moves — check it. Expand any postponed task: the dates block keeps showing due 9 Jun · 62 days ago in red while the row sits in Not started yet. This is the whole reason your version beats mine: the app never stops knowing the boiler service is late, it just stops asking you about it today.
  • Do the context badges keep you honest? The cards count overdue tasks including sleeping ones. So postponing empties the list but not the badge — house stays 3 overdue. If that feels like a nag, the badge should probably count only woken tasks, and then postpone really is a hiding place.
  • Does the counter still tempt you? With start-date postponing the counter is a weaker idea than it was — nothing is being rewritten, so there is less to be honest about. If you no longer reach for it, Q12(a) is settled by construction.
  • Waking up. Nothing here simulates tomorrow. Worth deciding out loud: when a postponed task's start date arrives, does it just reappear in Due today (it is still overdue), or does it need to announce itself?
